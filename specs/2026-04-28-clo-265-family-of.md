## 1. Problem Statement

PRD FR-13 requires that `Aggregator::LLMJudge` and `Aggregator::Vote` refuse to
start when the judge backend belongs to the same family as any reviewer
backend. Cross-family diversity is the loker thesis — same-family ballots
correlate and fail together.

Today there is no `Family` enum, no lookup table, and `ParallelFanOut::execute`
hardcodes `Attempt.family = Some("local".to_string())` (placeholder from
CLO-259). The strategy runner cannot enforce anything at runtime because it
cannot map a backend name to a family.

## 2. Acceptance Criteria

- [ ] **AC1**: `Family` enum exists in `src/family.rs` with these variants:
      ```rust
      #[non_exhaustive]
      #[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
      pub enum Family {
          Anthropic,
          Google,
          OpenAI,
          Zhipu,
          Local,
          Other(String),
      }
      ```
      `Display` impl returns lowercase snake_case (`"anthropic"`, `"other"`,
      etc.). `as_str()` returns `&'static str` for closed variants and
      `"other"` for `Other(_)` (the payload is not part of the discriminant
      string — `as_str` is a discriminant label, not a lossless round-trip).
      `Serialize`/`Deserialize` uses the same snake_case via
      `#[serde(rename_all = "snake_case")]`.
- [ ] **AC2**: `family_of(backend_id: &str) -> Family` lives in `src/family.rs`.
      It maps in-tree backend names with a static lookup table plus a special
      rule for tensorzero function names (D1 naming convention):
      | Input | Output |
      |-------|--------|
      | `"claude"` | `Family::Anthropic` |
      | `"gemini"` | `Family::Google` |
      | `"openai"`, `"codex"` | `Family::OpenAI` |
      | `"ollama"` | `Family::Local` |
      | `"bedrock"` | `Family::Other("bedrock".into())` |
      | `"tensorzero"` | `Family::Other("tensorzero".into())` |
      | `"tensorzero/<anything>"` | `family_of("<anything>")` (suffix-only passthrough) |
      | `"loker_<purpose>_<family>"` | parses suffix: `openai`→OpenAI, `anthropic`→Anthropic, `google`/`gemini`→Google, `local`/`ollama`→Local, otherwise `Other` |
      | any other string | `Family::Other(string.into())` |
- [ ] **AC3**: `PhaseError::FamilyOverlap { family: Family, count: usize }`
      variant added in `src/strategy/mod.rs` alongside `StrategyError`.
      ```rust
      #[non_exhaustive]
      #[derive(Debug, thiserror::Error)]
      pub enum PhaseError {
          #[error("family overlap: found {family} on {count} backends")]
          FamilyOverlap { family: Family, count: usize },
      }
      ```
- [ ] **AC4**: `enforce_cross_family(targets: &[&str]) -> Result<(), PhaseError>`
      helper in `src/family.rs`. It counts occurrences per `family_of` result.
      If any family appears more than once, returns
      `Err(PhaseError::FamilyOverlap { family, count })`. If all families are
      unique (or singleton), returns `Ok(())`. An empty slice returns `Ok(())`.
- [ ] **AC5**: `ParallelFanOut::execute` no longer hardcodes
      `family: Some("local".to_string())`. Instead it populates
      `Attempt.family` with `Some(family_of(&target.backend).to_string())`
      for every branch. This wires the resolver into the only strategy that
      currently emits the field.
- [ ] **AC6**: rustdoc on `Family` and `family_of` documents the extend-me
      pattern: "When adding a new known vendor, add a closed variant here and
      update `family_of`. Do NOT use `Family::Other(\"anthropic\")` — that is
      what `Family::Anthropic` is for. `Other` is reserved for self-hosted or
      future vendors that have not yet been promoted to a closed variant."
- [ ] **AC7**: Unit tests in `tests/family.rs` (or `src/family.rs` `#[cfg(test)]`):
      - `family_of_claude` → `Anthropic`
      - `family_of_gemini` → `Google`
      - `family_of_openai` and `family_of_codex` → `OpenAI`
      - `family_of_ollama` → `Local`
      - `family_of_bedrock` → `Other("bedrock")`
      - `family_of_tensorzero` → `Other("tensorzero")`
      - `family_of_tensorzero_function_name` (e.g. `"tensorzero/loker_d1_openai"`) → `OpenAI`
      - `family_of_tensorzero_anthropic_suffix` (e.g. `"loker_review_anthropic"`) → `Anthropic`
      - `family_of_unknown` → `Other("deepseek")`
- [ ] **AC8**: Unit tests in `tests/family.rs` for `enforce_cross_family`:
      - `mixed_families_ok` with `["claude", "gemini", "openai"]` → `Ok(())`
      - `all_anthropic_rejected` with `["claude", "loker_review_anthropic"]` →
        `Err(PhaseError::FamilyOverlap { family: Family::Anthropic, count: 2 })`
      - `three_same_family` → `count: 3`
      - `empty_slice_ok` → `Ok(())`
      - `single_backend_ok` → `Ok(())`
- [ ] **AC9**: The TDD decision record is embedded as a rustdoc comment on
      `family_of`: which source of truth wins and why. Verbatim text:
      > Source of truth: **loker-side backend naming convention** (variant of
      > workflow-config field). D1 round-trip spike proved TensorZero gateway
      > response carries no provider metadata; function name suffixes are the
      > only stable family signal. For non-gateway backends, the backend_id
      > string itself maps 1:1 to a vendor. See `docs/spikes/2026-04-25-tensorzero-roundtrip.md` §3.
- [ ] **AC10**: `make check` exits 0 (fmt + clippy + lib + integration tests).

**Verification method**:
- AC1-AC2, AC4, AC6-AC9: `cargo build` + diff inspection.
- AC5: `cargo test --test strategy_parallel_fanout` still passes + eyeball
  `Attempt.family` in the integration tests (they use `"local"` today; after
  the change, `family_of("a")` → `Other("a")` — test assertions must be
  updated from `"local"` to `"other"` or to the specific family if backend
  names are changed to real ones).
- AC7-AC8: `cargo test --test family`.
- AC10: `make check`.

## 3. Constraints

**Must**:
- Add `pub mod family;` to `src/lib.rs` so downstream code can import the enum.
- Keep `Backend` trait and `BackendConfig` untouched. This is a lookup layer
  above the backend, not a backend capability or config schema change.
- Do NOT add `BackendId` newtype in this task. The codebase uses `&str` /
  `String` everywhere for backend names; introducing a newtype would be a large
  cross-file refactor out of scope for an S task. `family_of` takes `&str`;
  if a future task introduces `BackendId`, it can add `impl From<&BackendId>`.
- `Attempt.family` stays `Option<String>` for backward compatibility with the
  schema. `Family::to_string()` is the bridge.
- Handle the `tensorzero/` prefix split in `family_of` so the workflow loader
  (CLO-261) can already pass `backend_id = "tensorzero/loker_review_anthropic"`
  and get the right answer.

**Must-not**:
- Modify `StrategyError` existing variants. `PhaseError` is a new enum; LLMJudge
  and Vote aggregators (future tasks T-017/T-019) will call `enforce_cross_family`
  and convert `PhaseError` into their own error at the call site.
- Touch `src/backend/*` impls. Family resolution is external to the backend.
- Add a new dependency. `thiserror` and `serde` are already direct deps.
- Wire the check into `LLMJudge` or `Vote`. Those aggregators are T-017/T-019.
  This spec only lands the primitive (`Family`, `family_of`, `enforce_cross_family`).

**Prefer**:
- `#[non_exhaustive]` on `Family` so new closed variants are additive.
- `#[non_exhaustive]` on `PhaseError` so future phase-level errors are additive.
- Module-level tests inside `src/family.rs` for the pure lookup function; a
  separate `tests/family.rs` only if integration-level mocking is needed (it
  is not — the function is pure).

## 4. Decomposition

Four sub-tasks. Each independently testable.

1. **ST1: Land `Family` enum and `family_of` resolver.**
   - New file `src/family.rs`.
   - `Family` enum with `Display`, `Serialize`, `Deserialize`, `as_str()`.
   - `family_of(backend_id: &str) -> Family` with the full lookup table and
     tensorzero suffix parsing.
   - rustdoc including the extend-me note (AC6) and the TDD decision record (AC9).
   - `#[cfg(test)] mod tests` covering AC7.
   - Add `pub mod family;` to `src/lib.rs`.
   Done when `cargo test --lib family` is green.
   Files: `src/family.rs`, `src/lib.rs`.

2. **ST2: Land `PhaseError` and `enforce_cross_family`.**
   - In `src/strategy/mod.rs` (next to `StrategyError`): add `PhaseError` enum
     with `FamilyOverlap` variant.
   - Re-export `PhaseError` from `src/strategy/mod.rs` so `use crate::strategy::PhaseError`
     works.
   - In `src/family.rs` add `enforce_cross_family` helper and tests covering AC8.
   Done when `cargo test --lib family` and `cargo test --lib strategy` are green.
   Files: `src/family.rs`, `src/strategy/mod.rs`.

3. **ST3: Wire real families into `ParallelFanOut`.**
   - In `src/strategy/parallel_fanout.rs`, replace the two
     `family: Some("local".to_string())` sites with
     `Some(family_of(&target.backend).to_string())`.
   - Update assertions in `tests/strategy_parallel_fanout.rs` where tests
     assert `a.family == Some("local")` to assert `Some("other")` instead
     (the mock backends are named "a", "b", "c" which map to `Other`).
   Done when `cargo test --test strategy_parallel_fanout` is green.
   Files: `src/strategy/parallel_fanout.rs`, `tests/strategy_parallel_fanout.rs`.

4. **ST4: Snapshot / regression guard.**
   - Run `make check` (fmt + clippy + full test suite).
   - Commit with message `feat(CLO-265): family_of lookup and cross-family check`.
   Done when `make check` passes.
   No new files.

**Dependency order**: ST1 and ST2 are independent (ST2 imports the `Family` type,
but `family.rs` already exists after ST1). ST3 depends on ST1. ST4 depends on
ST1-ST3.

## 5. Evaluation

| # | Test | Expected Result | How to Run |
|---|------|-----------------|------------|
| 1 | `family_of` maps every in-tree backend name | All assertions in AC7 pass | `cargo test --lib family` |
| 2 | `family_of` parses tensorzero suffixes | `"loker_d1_openai"` → `OpenAI`; `"tensorzero/loker_review_anthropic"` → `Anthropic` | `cargo test --lib family` |
| 3 | `enforce_cross_family` accepts diversity | `["claude", "gemini", "openai"]` → `Ok(())` | `cargo test --lib family` |
| 4 | `enforce_cross_family` rejects overlap | Two Anthropic backends → `FamilyOverlap { Anthropic, 2 }` | `cargo test --lib family` |
| 5 | `ParallelFanOut` emits real families | Mock backend "a" → `family` field `"other"` | `cargo test --test strategy_parallel_fanout` |
| 6 | Pre-merge gate green | fmt + clippy + all tests | `make check` |

**Edge cases to verify**:
- `family_of("")` → `Other("")` (empty string, no panic).
- `family_of("tensorzero/")` → `Other("")` (empty suffix after slash).
- `family_of("loker_")` → `Other("loker_")` (no suffix to parse).
- `enforce_cross_family` with `Other("a"), Other("b")` → `Ok(())` (two distinct
  `Other` families are different).
- `enforce_cross_family` with `Other("x"), Other("x")` → `FamilyOverlap` (same
  `Other` payload counts as overlap).
