# Discovery Report: CLO-286 — Attempt Directories

## Problem Statement

Loker needs per-attempt archive directories (`runs/<id>/attempts/<phase>/<n>/`) so that failed retries don't clobber prior outputs. Each attempt's artefact gets its own subdirectory; the manifest entry's `attempt` field pins which attempt the canonical artefact came from.

## Who is Affected

- The run-state persistence subsystem (T-025 markers, T-024 manifest writer, T-031 resumability).
- Downstream crash-recovery and resume logic that must distinguish between fresh and retried phases.

## Current Behaviour vs Desired

**Current**: 
- `next_attempt()` scans `markers/<phase>.started.*` files.
- Manifest entries have `attempt: Option<u32>` but it's unpopulated.
- Failed attempt debris has no dedicated archive location.
- Producers write directly to `<phase>/<artefact>` without attempt scoping.

**Desired**:
- `attempts/<phase>/<n>/` holds failed-attempt debris per D3.
- `next_attempt()` scans both markers and `attempts/<phase>/` dirs for crash resilience.
- Manifest entries populate `attempt`.
- Best-effort `latest` symlink/pointer for human inspection.

## Discovery Findings

### Existing Code (Baseline Score: 8/10)

`src/run_state/` is well-structured with four modules already shipped under CLO-283/CLO-284:

- **`atomic.rs`** — `atomic_write(path, contents)` primitive using `tempfile::NamedTempFile → fsync → rename → parent-fsync`.
- **`markers.rs`** — `MarkerWriter` with `write_started/completed/failed`. `next_attempt(markers_dir, phase) → u32` already exists but only scans `*.started.*` markers.
- **`heartbeat.rs`** — Tokio-based heartbeat writer with fake-clock injection.
- **`order.rs`** — `PhaseOrderGuard` state machine enforces `Idle → Started → ArtefactWritten → ManifestAppended → Completed`.
- **`load.rs`** — `RunState::load(run_dir)` reads manifest, orphan-sweeps, and verifies per-entry sha256.

`src/manifest.rs` has `ManifestEntry { attempt: Option<u32> }` declared but not populated.

`tests/run_state_markers.rs` covers round-trip markers, atomic write, `next_attempt`, concurrent writers, and PhaseOrderGuard.
`tests/run_state_load.rs` covers manifest loading, orphan sweep, stale heartbeat, and corrupt-entry handling.

### Critical Conflict Discovered

The CLO-286 issue description implies **Approach B** (all attempts under `attempts/<phase>/<n>/`, manifest names reference attempt-scoped paths, canonical is latest symlink). However, **`docs/run-state.md`** (D3, CLO-245) **explicitly rejected Approach B** in favour of **Approach A**:
- Canonical artefacts live at `<phase>/<artefact>` (stable, no indirection).
- `attempts/<phase>/<n>/` holds **failed-attempt debris only**.
- Manifest paths remain stable and canonical.

Roadmap T-027 confirms: *"Canonical artefact path remains the latest successful one."*

**Resolution**: Proceed with D3 Approach A. The issue's acceptance criteria are reconcilable:
- "Producers write into `attempts/<phase>/<n>/`" means **producers use attempt-scoped temp dirs during the attempt**, then atomically promote the final artefact to the canonical path on success. Failed attempts are archived to `attempts/<phase>/<n>/`.
- Manifest `name` is canonical (e.g. `design/design.md`), `attempt` is the metadata field.
- `latest` pointer is a convenience symlink to the latest **completed** attempt's canonical path.

## Approaches Considered

### 1. D3 Approach A — Canonical path + attempt-archive (Chosen)
- **Summary**: Keep canonical path at `<phase>/<artefact>`; only failed attempts go to `attempts/<phase>/<n>/`. Successful artefacts stay at canonical path.
- **Pros**:
  - Matches existing D3 protocol and all shipped code.
  - Stable canonical paths — no symlink/pointer indirection for readers.
  - `rename(2)` atomic promotion; no pointer race conditions.
  - Minimal change to existing producers.
- **Cons**:
  - Slightly more complex: need "attempt dir → promote on success" logic.
  - Human operators see attempt debris in `attempts/`, canonical in `<phase>/`.
- **Effort**: M
- **Risk**: Low

### 2. D3 Approach B — All attempts under attempts/ (Rejected)
- **Summary**: All attempts under `attempts/<phase>/<n>/`; canonical is a symlink/pointer to latest.
- **Pros**:
  - Unified layout; every attempt has a home.
  - Matches the issue description's literal framing.
- **Cons**:
  - Contradicts D3 explicit decision and T-027 roadmap.
  - Symlink portability issues (Windows unprivileged blocking).
  - Pointer race conditions on concurrent writers.
  - Requires rewriting markers, manifest, and load logic already shipped.
- **Effort**: L
- **Risk**: High

## Chosen Approach

**D3 Approach A** — Canonical path with attempt-scoped writes and failed-attempt archive.

Reason: D3 is an explicit architecture decision already ratified and implemented across CLO-283/CLO-284. Approach B would require rewriting shipped code and re-litigating the decision. The issue's functional requirements (attempt numbering, attempt dir, manifest `attempt` field) are fully satisfiable under Approach A.
