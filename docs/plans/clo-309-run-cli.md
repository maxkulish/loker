## Sub-tasks (remaining)

### P1 · Fix `{{ spec }}` and `{{ var.<name> }}` template resolution  ✅ DONE

**Files**: `src/template/context.rs`, `src/workflow/mod.rs`

The issue was that MiniJinja's template engine couldn't find `{{ spec }}` and `{{ var.foo }}`
because:
1. `var` namespace was only inserted when non-empty → always insert it (even empty)
2. The test workflows need sequential step dependencies (not parallel) to test flags independently

**Status**: ✅ Tested and passing.

### P2 · Wire `--rerun` marker deletion  ⏳ DEFERRED TO T-041

**Files**: `src/run_state/markers.rs`, `src/workflow/mod.rs`

The phase-based workflow runner uses `MarkerWriter` to write `*.completed` / `*.failed` markers.
`--rerun phase=X` should delete these markers so the runner re-executes the phase.

However, the current `loker run` uses the **step-based** `WorkflowRunner` which is stateless —
it always executes all steps from scratch. The phase-based runner is not yet wired to the CLI.

**Decision**: Defer marker deletion logic to T-041 when the phase-based runner is wired to the CLI.
The `--rerun` flag syntax is accepted and validated now for forward compatibility.

### P3 · Help text verification  ✅ PASSED

**Files**: `src/main.rs`

The `loker run --help` output should clearly document `--spec`, `--var`, and `--rerun`.

```
loker run <workflow>
  --spec <path>            Path to a spec file to inject into the first phase context ({{ spec }})
  --var <key=value>        Template variables (repeatable, e.g. --var key=value)
  --rerun <phase=name>     Force re-execution of a completed phase (repeatable)
```

**Status**: ✅ Help text is auto-generated by clap derive macros from doc comments.
